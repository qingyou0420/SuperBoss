# 超级老板 SuperBoss — 需求定稿

> 版本：v1.0（冻结）
> 定稿日期：2026-08-09
> 项目根目录：D:\SuperBoss

---

## 1. 产品定位

公司内部专属虚拟工作台系统，部署于腾讯云 Linux 服务器，绑定域名 nightforest.com（备案审批中）。
仅供老板（OWNER，唯一）与 10 人以内员工使用，**不对外开放**。

一句话定位：**老板（主人）的超级助理霜月 + 员工的资料库与学习库。**

员工各自拥有自己的大模型 App，工作台内不为员工提供任何大模型问答服务——霜月 Agent 仅服务老板一人。

## 2. 角色定义

| 角色 | 人数 | 权限概述 |
|---|---|---|
| OWNER（老板） | 1（硬编码不可降级） | 全权限：云盘、项目管理、成本核算、公司流水收益表、霜月 Agent 对话、待办处理、账号管理 |
| STAFF（员工） | ≤9 | 纯消费型：浏览/下载资料库与学习库、上传成本凭证与排班表、提交问题与需求、查看回复状态 |

**无 ADMIN 主管层级。**

## 3. 功能模块

### 3.1 云盘存储
- 文件上传（分片/断点续传）、下载（预签名 URL，带权限校验）、管理
- 目录结构：`项目/分类/日期` 三级组织
- 上传文件触发病毒扫描（ClamAV）

### 3.2 文档版本链管理
- 同一文档以版本链组织：**初版上传即锁定存档**（不可覆盖），后续修订产生 v2…vn
- 每版记录：修改日期、修改人
- 每次修订，霜月自动生成：
  - 修改日期时间轴（自动累积）
  - 本次修改要点（三条以内简明归纳）
  - 版本说明卡（附在文档详情页）
- 老板标记「定稿」后，霜月自动生成**最终版 vs 初版逐段差异归纳报告**
- 技术路线：docx/txt/md 走文本 diff + 大模型语义归纳；扫描件 PDF 走 OCR 后对比

### 3.3 霜月 Agent（仅 OWNER 可用）
- **单人会话架构**：Agent 服务只校验 `role=OWNER` 的会话，员工请求在网关层直接拒绝
- 文档整理流水线：文件上传 → Redis 队列异步处理 → OCR/文本抽取 → 大模型生成摘要、标签、建议标题 → 规则引擎归档 → 重命名格式 `【项目名】YYYYMMDD_标题_来源`
- 知识归纳：接收外部大模型生成的知识点文档，归纳整理后经**老板审核**发布到学习库
- 霜月**从不直接对员工发言**；所有对外内容经老板确认后以公司名义推送

### 3.4 异步协作流转（员工 ↔ 老板）
- **成本凭证流**：员工上传（兼职名单 Excel / 采购截图）→ 霜月后台 OCR/归类/生成入账草稿 → 工作台待办提醒老板 → 老板一键确认入账
- **提问需求流**：员工表单提交 → 霜月汇总归类生成老板待办 → 提醒老板 → 老板回复（霜月可代拟回复稿，老板审定）→ 以公司名义推送员工
- 员工可在「我的提交」查看回复状态

### 3.5 项目管理
- 多项目区分，项目模板预置标准流程阶段（立项→开发→测试→交付→复盘）
- 生成可拖拽调整的项目时间线
- 重要节点提醒：节点前 3 天、1 天，在工作台提醒**项目全员**

### 3.6 人员排班
- 员工上传排班表（Excel/截图均可），霜月解析为结构化排班数据
- 排班与项目节点**冲突自动检测**（如交付日无人当值 → 提醒老板）

### 3.7 成本核算
- 兼职名单 Excel 自动解析；采购截图走 OCR（腾讯云 OCR / PaddleOCR）提取金额、商户、日期，人工确认后入账
- 每条成本强制挂 `project_id`
- 报表自动计算各项目总成本、收入、利润

### 3.8 公司流水收益计算表（仅 OWNER，API 层硬锁）
- 命名规范：使用「公司」，**不带「总」字**
- 数据源自动打通：成本核算模块确认入账后金额自动汇入；收入侧老板/霜月按项目录入
- 霜月维护：按「项目 × 月份」双维度汇总，自动计算毛利、净利、利润率
- 异常项（成本突增、回款逾期）标红并生成老板待办
- 看板：月度视图 / 项目视图 / 现金流趋势图，支持导出 Excel
- **权限硬锁**：API 层只认 `role=OWNER`，非前端隐藏

### 3.9 提醒体系（分级路由）
| 提醒类型 | 接收人 | 通道 |
|---|---|---|
| 项目重要节点 | 项目全员 | 工作台提醒 |
| 待办事项（凭证待确认/员工提问/异常账目/排班冲突） | 仅老板 | 工作台待办 |

### 3.10 一键部署迭代
- GitHub/Gitee 私有仓库 + Webhook 触发服务器 `deploy.sh`
- 流程：拉代码 → `docker compose build` → 数据库 migration → 滚动重启 → 失败自动回滚上一镜像
- 老板后台提供「立即更新」按钮

### 3.11 UI 双形态 + 彩蛋
- **老板端**：收益看板、待办中心、霜月对话框、云盘管理、账号管理
- **员工端**：资料库、学习库、我的提交（上传凭证/排班/提问入口）
- **Q 版吐槽小人彩蛋**：老板形象 Q 版小人随机冒出吐槽后消失，活跃气氛
  - 老板端与员工端吐槽文案库**分开配置**（员工端保持安全搞笑）
  - 技术：Lottie 动画 / 雪碧图随机触发
  - 文案示例：
    - 上传凭证：「又让老板花钱了？我看看发票……啧。」
    - 收益看板：「这数字，够买一箱奶茶了。」
    - 深夜登录：「凌晨还在卷？行吧，我陪你。」
    - 员工端：「安静！老板在看后台数据。」
    - 导出 Excel：「发财了发财了（并没有）」

## 4. 安全设计

### 4.1 认证方案
- 本地用户名和密码登录，**无公开注册页**
- 唯一 OWNER 通过交互式运维命令初始化；老板后台创建 STAFF 账号并分配项目
- STAFF 首次登录必须修改一次性临时密码；密码不可恢复，只能由 OWNER 重置
- 双 Token 会话：Access Token 2 小时 + Refresh Token 14 天
- 离职：一键禁用 + 踢下线（Refresh Token 立即吊销）

### 4.2 私有化访问控制（四道闸，由外到内）
1. 安全组 + 云防火墙：仅放行 443 端口
2. Nginx IP 白名单：办公网/家庭固定 IP
3. 本地账号白名单：无公开注册，禁用账号立即失效
4. RBAC + 行级过滤：应用层兜底

### 4.3 数据权限模型
- **行级隔离**：所有业务查询强制附加 `project_id` 过滤
- **列级隔离**：成本/利润/收益等敏感字段仅 OWNER 可见
- **文件级**：云盘按项目目录授权
- 权限判断永远在后端做；Agent 调用工具时携带调用者身份，工具内部再校验一次——不信任前端、不信任提示词
- 每次请求流程：JWT 解析 → RBAC 策略校验 → 数据行过滤 → 审计日志

### 4.4 审计日志
- 全操作留痕：谁上传了什么、谁改了成本数据、凭证确认记录等，可查可追溯

### 4.5 备案过渡期
- 当前仅在 OWNER 的 Windows 电脑通过 `app.localhost` 私人测试，不开放外网或公司访问
- 域名、腾讯云、公司内网多人访问与 Moonbox 入口在备案完成后另行设计和验收

## 5. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue3 + Element Plus（或 React + Antd） | 管理后台生态成熟 |
| 后端 | Node (NestJS) 或 Python (FastAPI) | 单体即可，10 人规模无需微服务 |
| 数据库 | PostgreSQL + pgvector | 业务数据与向量检索一库搞定 |
| 文件存储 | MinIO（自建 S3） | 分片上传、预签名下载 |
| 缓存/队列 | Redis + BullMQ | 会话缓存、异步任务、定时提醒 |
| Agent | LangGraph / 自研编排 + 混元或 DeepSeek API | 密钥仅存服务端环境变量 |
| 部署 | Docker Compose + Caddy/Nginx | 单机 4C8G 轻量应用服务器足够 |

## 6. 数据库核心表

| 表 | 用途 |
|---|---|
| users | 本地账号（用户名、密码哈希、角色、状态、强制改密标记） |
| projects / project_members | 项目与成员 |
| files | 云盘文件元数据 |
| doc_versions | 文档版本链：parent_doc_id、版本号、修改人、修改要点、定稿标记 |
| knowledge_cards | 学习库知识点（发布状态字段实现审核闸门） |
| cost_entries | 成本记录（强制 project_id、凭证关联、确认状态） |
| ledger_entries | 公司流水表：项目、月份、收入/成本类型、金额、凭证关联 |
| shift_schedules | 排班：员工、日期、时段、所属项目 |
| staff_requests | 员工提问与需求（状态机：待处理/已回复） |
| todos | 老板待办：类型、来源、状态 |
| audit_logs | 审计日志 |

## 8. 里程碑建议

1. **M1 骨架**：仓库初始化 + Docker Compose + 认证中心 + 云盘基础上传下载
2. **M2 核心**：文档版本链 + 霜月整理流水线 + 资料库/学习库
3. **M3 协作**：员工提交流转 + 待办中心 + 项目时间线 + 排班
4. **M4 财务**：成本核算 + 公司流水收益表
5. **M5 打磨**：Q 版小人彩蛋 + 一键部署 + 域名切换上线
