给老板的一页纸：

2. **N37（召回排序偏泛词）按决策 AA 两步都做了，实测过关。** 候选词先按"命中数 ≤ 活跃记忆 30%"过滤泛词、再按命中数**升序**取 8 个稀有词；`OR` 之后不再只按 `importance` 截断，而是对每条记忆按"命中候选词数 + Σ 1/命中数"计分、`score desc, importance desc` 取 8。新单测就是第六版要的那组：60 条例会噪声 `importance = 4` + 1 条星野 `importance = 3`，星野**排第一**。本机复测噪声 `importance = 3 / 4 / 5` 三档星野都排第一，500 条记忆下四句验收 6–19 ms。**边界（N48）**：专名本身出现在 > 30% 记忆里时会被当泛词丢掉（实测 100 条里 40 条含"星野"，问"星野的对接人是谁"只回对接人两条、零条星野）——这是第六版自己给的 30% 规则的直接后果，见第五章。

8. **顺序建议**：先修 N44（种子给两个账号真名 + spec 在成员页截图前断言"操作失败。"不可见且至少一行 + 前端对空 `display_name` 回退到用户名），dispatch 一次重抓、只提交 `members.png`；顺手把 N45 / N49 两个十行以内的改掉；然后对一次性库跑 `llm_three_round.py` 贴报告。N48 的 30% 边界拿到决策 AF 再动。见第五章。

### 3.1 门

**N44（实测，中）成员页基线是报错态，视觉门把一个真实 bug 锁成了"正确"。** `members.png`（1280 × 800 全页）：通栏 → 标题"成员" + 右上"添加" → **标题正下方一行红字"操作失败。"** → 表头"姓名 / 用户名 / 角色 / 已禁用 / 最近登录" → 居中灰字"还没有成员"。而此时库里明明有 `ownere2e`（OWNER）与 `staffe2e`（STAFF）两个账号。**根因链**（每一环已验证）：`seed_acceptance.py` L111 `display_name=""` → `users/schemas.py` L49 `OwnerUserRead.display_name: str` 原样返回 `""` → `web/src/api/users.ts` L70-77 `text()` 要求 `length ≥ 1`、L113 `!text(value.display_name)` → `throw new UserContractError()` → `UsersPage.vue` L50-59 `load()` 的 `catch` → `userErrorMessage()` → `formatRequestError(..., errorCopy.generic)` = "操作失败。"，`users` 保持 `[]`。**实测**（探针 d）：jsdom 里用这两条数据（`display_name: ""`，其余合法）调 `createUsersApi(createHttpClient({ adapter })).list()` → `UserContractError`，`userErrorMessage()` → `"操作失败。"`。这与第四版 4.2 描述的 `members-win32.png`（"红字'操作失败。'…'还没有成员'"）是**同一张图、同一根因**，第五版删图时没查为什么会错，第六版 G-9 写了"成员页基线必须是正常空态"，本轮照旧抓了回来。同时它也是**产品 bug**：服务端 `StaffCreate.display_name min_length=1`（L18）挡住了 UI 建号，但任何绕过 UI 的账号（种子、`manage_local_owner.py`、手工 SQL）一旦 `display_name` 为空，OWNER 的成员页整页只剩"操作失败。"，一个坏行拖死全表。**修法**（G-11）：(1) 种子给两个账号真名（如 `"验收老板" / "验收员工"`，或直接用用户名）；(2) 前端 `user()` 对空 `display_name` 不抛错、回退显示用户名（或服务端 `OwnerUserRead` 保证非空）——两者都做；(3) `visual-pages.spec.ts` 成员页截图前加 `await expect(page.getByText('操作失败。')).toHaveCount(0)` 与 `await expect(page.getByRole('row')).toHaveCount(≥ 2)`；(4) dispatch 重抓，只提交 `members.png`。

### 3.2 服务端

**N48（实测，低）30% 泛词规则会把高频专名当泛词丢掉。** `service.py` L770-772：命中数 > `total_active * 0.3` 的词进不了 `specific`，只要还有任何一个稀有词，它们就**整体不参与检索**。探针 b：100 条活跃记忆，40 条 "星野合作第 N 次沟通纪要"、58 条日常、2 条含"对接人"。问 "星野那边最近怎么样"（只有星野一个有效词）→ 回退 `positive`，命中 8 条星野 ✓；问 **"星野的对接人是谁"** → "对接人" 2 命中入选、"星野" 40 命中（> 30）被丢 → 只回两条对接人、**零条星野**。对一个天天谈同一个客户的老板，专名恰恰是高频词。第六版 AA 给的就是 30%，这是规则本身的代价，不是实现错误。**修法**（决策 AF）：泛词只在**计分**时降权、不在检索时丢弃——`ranked` 保留全部 `positive`（按升序取前 8 仍可），`OR` 候选 `.limit(200)` 改为按 `importance desc, created_at desc` 排（同时修 N50），计分公式 `Σ 1/hits` 本来就会让 40 命中的词只值 0.025 分；或把阈值改成 `max(0.3 * total, 20)` 并对连续 ≥ 2 个汉字的整 token（非 2-gram 切片）免疫阈值。单测：探针 b 那组，"星野的对接人是谁"必须同时回星野与对接人。

**N50（已验证，极低）`recall` 候选 `.limit(200)` 无 `ORDER BY`。** L778-790 `select(AgentMemory).where(ACTIVE, or_(*matches)).limit(200)`——超过 200 条命中时取哪 200 条由 PostgreSQL 扫描顺序决定，不稳定。目前稀有词过滤让命中数很少触及 200；N48 修法若保留泛词就会触及。加 `order_by(importance.desc(), created_at.desc())`。

**N47（已验证，低）`GET /agent/recall` 是有副作用的读。** `router.py` L199-204 直接 `return await service.recall(q)`；`service.recall` L808-809 对每条返回记忆 `recall_count += 1`、`last_recalled_at = utcnow()`；`core/db.py` L39-50 `get_session` 在无异常时 `commit()`。每次探测都在改"被召回次数"统计，`llm_three_round.py` 跑一遍就把星野记忆的计数多加两次。**修法**：`recall(query, *, touch: bool = True)`，探测端点传 `touch=False`；或探测端点里 `await session.rollback()` 后返回。

### 3.3 前端

**N45（已验证，低，可访问性）页头隐藏文件输入仍在 Tab 序里且无标签。** `DrivePage.vue` L251-258 `<input id="drive-upload" class="sr-only" type="file">`：`.sr-only`（`base.css` L35-45）只是视觉裁掉，元素仍可聚焦、仍在可访问性树里，没有 `<label for>`、`aria-label`、`tabindex="-1"` 或 `hidden`。键盘用户 Tab 到页头会先停在一个看不见的"选择文件"、再到"上传"——N39 的"两次停在上传"变成"一次停在看不见的东西上"。另外没有 `multiple`，页头一次只能选一个文件，而整页拖放（`onDropped` L219-225）支持多文件——同一动作两种能力。**修法**：`<input … hidden multiple aria-hidden="true" tabindex="-1">`（`hidden` 元素仍可被 `.click()` 触发文件选择），或至少 `tabindex="-1"` + `aria-label`。

**N49（已验证，低，tip spam）对话页回形针上传完"扫描中"留在输入框旁。** `MultipartUploader.vue` L70 完成后 `status = driveCopy.scanning` 不清空，L122-123 `<p role="status">` 在 `compact` 模式一样渲染；`ChatPage.vue` L362-369 用的就是 `compact`。组件根 `.uploader` 是 `display: grid; gap: 8px`，"扫描中"会挂在回形针图标正下方、直到下一次上传或离开页面，同时 `ChatPage.vue` L355-360 还显示 `pendingFileName`——同一件事两处字。N38 修的是网盘页头那一份，这一份是同一段代码。**修法**：删掉组件里两个 `<p>`，`completed / error` 交给父组件（对话页已有 `pending-file` 行可承载"扫描中 / 失败"一词）；或 `compact` 时不渲染。
